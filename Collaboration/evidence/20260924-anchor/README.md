# 部屋の置き直し（task017・018）の証拠（2026-09-24、レビュー前）

撮影: Claude Opus 5.5。Windows ビルドを `--desktop --autostart --simulate-drift` で起動し、PrintWindow で約0.85秒おきに撮影（人の操作なし）。`--simulate-drift` は周回ごとに desktop のカメラ（体験者の代わり）を決まった量だけずらす。

- `contact-sheet.png`: 全フレーム。周回1・3・5（小さいずれ: 中心から (0.15,0.10)・20°、(−0.20,−0.05)・−30°）は**毎回同じ構図**（机・時計・扉）で始まる＝体験者が動いても定位置から始まる。周回2・4（大きいずれ: (0.55,0.35)・40°、(−0.60,−0.40)・−120°）は前方の扇形が安全範囲に収まらないため正面の向きが補正され、カメラは部屋の後ろ側を向いて始まる（体験者は正面から鳴る時計の音の方へ向き直る想定）。
- `placement-log.txt`: 置き直しのたびのログ（位置、頭の yaw、正面の yaw、補正の有無と角度、fits）。補正は −135°・+165° と大きい。
- `checks.png` / `.txt`: モデル19件＋RoomAnchor 7件 PASS。
- ビルド: コンパイル エラー0・警告0、Player.log の例外0。

## 実験前に共有する発見

1.6m 四方・余裕0.1m・前方半径0.45m では、補正なしで済むのは中心からおよそ0.25m以内。それを超えると補正角が大きく（ほぼ振り返る）なる。実機の実験で、許せる補正の大きさと、Reach・Margin・扇形の角度を調整する（ユーザーと合意済みの進め方）。
