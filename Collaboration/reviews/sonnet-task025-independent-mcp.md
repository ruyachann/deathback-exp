## 検出事項

### [中] タイル境界で木目・床目が不連続になる可能性（`FloorTexture()` / `WoodTexture()`）
`Texture()` は `wrapMode=Repeat` を設定しており、床(`FloorTexture`)・木目(`WoodTexture`)の"継ぎ目"や"板の並び"自体は周期がテクスチャサイズの約数になっているためシームレスですが、木目模様（`grain`）に使われている `Mathf.Sin(x*.19f+...)`（周期 ≈33.1px、512pxに対し非整数の15.48周期）や `WoodTexture` の `bend`（周期 ≈165.3px / 571.2px、256pxに対し非整数）は **タイル1枚のサイズで割り切れない周波数** です。Repeatで敷き詰めた際、x=0とx=size-1の境界で木目の位相が揃わず、継ぎ目線として視覚的に見える恐れがあります。`WallTexture()` は `px=2πx/size` で正規化されておりシームレスですが、`FloorTexture`/`WoodTexture` の grain 成分には同様の配慮がありません。
- トリガー: 床・机・扉などタイル境界が視界に入る角度（特に机の天板や扉パネルの継ぎ目付近）。
- 修正案: grain 波の周波数を `2π*n/size`（n は整数）に丸める、または `px=2πx/size` 形式に統一する。

### [受入条件未達] マテリアルが不必要に複製されている（`Shape()` / `Detail()` → `Material()`）
タスク受入条件「マテリアルの数を不必要に増やさない（同じ素材は共有する）」に対し、`Shape`/`Detail` は呼び出しごとに `Material()` で新規インスタンスを生成します。例えば
```
foreach (var x in new[]{-.63f,.63f}) foreach (var z in new[]{.24f,.80f})
    Detail("Desk leg", ... wood texture, textureScale ...);
```
（`Detail("Desk leg",...)` 呼び出し部分）や `Chair leg` の4回ループは、色・テクスチャ・スケールが完全に同一であるにもかかわらず毎回別マテリアルを生成しています。テクスチャ自体（`floorTexture`/`woodTexture`等）は事前生成して共有していますが、マテリアルの共有ロジックがありません。
- 修正案: 同一パラメータの `Material` をキャッシュする小さな辞書（key: color+texture+smoothness等）を `Material()` 呼び出し側に追加する。

### [情報] `WoodTexture` が要件「床より細かく控えめ」を満たしているか要目視確認
`FloorTexture` の grain 振幅は `Sin(x*.19f+...)*1.6f`（+継ぎ目±35程度）、`WoodTexture` の grain 振幅は `Sin(...)*2.4f + Sin(...)*1.4f`（合成で最大±3.8）です。単純な振幅比較では `WoodTexture` の方が変動幅が同等かむしろ大きく、コード上「控えめ」であることは自明ではありません。周波数はわずかに高い（細かい）ので「細かい」要件は満たしていそうですが、「控えめ」は数値だけでは判断できず、目視確認が必要です。

### [情報] 木製オブジェクトへの適用漏れ
`Picture frame` / `Picture`（`darkWood`色）に `texture` 引数が渡されておらず単色のままです。対象外リストには含まれていないため、統一感の観点では適用漏れの可能性がありますが、タスクは「全木製物への適用必須」とまでは書いておらず、致命的ではありません。

### [情報] 非圧縮フォーマット（`TextureFormat.RGB24`）
4枚合計は「数MB以内」の受入基準は満たしますが（概算: Floor 512²×RGB24+mip ≈1MB、他3枚256²×RGB24+mip ≈0.26MB×3）、Quest3実機ではVRAM上も非圧縮のままになります（`Compress()`等の呼び出しなし）。要件を満たしてはいますが最適化の余地として記載します。
