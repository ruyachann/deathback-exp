# 027 — キャリブレーションの長押しの手応え

状態: **受入（2026-09-25、reviews/task027-exchange-20260925.md）**。計画 Claude Opus 5.5。実装 Claude Sonnet 5。レビュー 実装とは別セッションの Sonnet と GPT-5.6 Sol。

## 背景

キャリブレーション画面で A/X を1秒長押しすると決定する（task021）。今は押している間に何も変化がなく、体験者は「押せているのか」「あとどれくらいか」が分からない。決定した瞬間の手応えもない。

## 設計

1. **進み具合の表示**（CalibrationView、PrivateLayer 8、観客には見せない）: 足元の印の周りに、長押しの進み具合（0〜1）に合わせて伸びる円弧（リング）を表示する。0 のときは表示しない。色は足元の印に合わせ、1 に近づくほど明るく。床の少し上（他の線と重ならない高さ）。`CalibrationView.SetHoldProgress(float t)` のような公開関数で渡す。
2. **案内の文字**: 長押し中は案内の2行目を「そのまま押し続けて…」に変える（放すと元に戻る）。
3. **決定の手応え**: 決定した瞬間に、短い確認音（既存の ProceduralAudio の音を流用してよい。時計の音＝死の痕跡の Chime は**使わない**）を頭の位置で鳴らし、VR では両手に短い振動（`rig.Haptic`）。
4. **証拠用** `--auto-calibrate`: 今の「2秒後に決定」を「1秒待ってから1秒かけて長押しを模擬し（進み具合の表示が伸びる）、満ちたら決定」に変える。決定までの合計時間は従来どおり約2秒。
5. 途中で放したら進み具合は 0 に戻る（今の挙動どおり）。C キーの即時決定、境界外の警告、同一フレームの排他（operatorCommandConsumed）は変えない。

### 追修正（2026-09-25、撮影で判明。計画担当 Opus 5.5）

`--auto-calibrate` の計時が起動直後から始まるため、Unity の起動画面（スプラッシュ）の表示中に決定まで終わってしまい、キャリブレーション画面が一度も映らない（task021 の証拠もこのため `--auto-calibrate` なしで撮っていた）。→ `--auto-calibrate` の計時は `UnityEngine.Rendering.SplashScreen.isFinished` が true になってから始める。通常の操作（長押し・C）には影響させない。

追記: スプラッシュ終了を待っても、終了直後の約1.5秒は画面の取り込みに映らない（撮影で確認）。`--auto-calibrate` は証拠専用なので、長押しの模擬を始めるまでの待ちを **1秒 → 3秒** に延ばす（決定までは約4秒）。

### 追修正2（2026-09-25、独立レビューと撮影。計画担当 Opus 5.5）

Sol request_changes（`sol-task027-independent-mcp.md`）、計画担当の撮影でも同じ2点を確認。Sonnet の独立レビューは時間切れ（300秒）のため修正後に改めて行う。採用:
1. （中）リングが前方の扇形と重なる部分で隠れて細く見える → リングを扇形より上（高さ）に置き、他の線（外枠・余裕の枠）とも重ならないようにする。必要なら描画順（renderQueue）でも扇形より後に描く。
2. （中）起動直後の長いフレームの unscaledDeltaTime で自動の計時が一気に進む → 自動の計時と長押しの計時に加える dt を 1 フレームあたり最大 0.1 秒に制限する（長押しは実時間で約1秒の体感を保つ）。
