# 実機クイックチェック（Quest 3 / Quest 3S）

Quest が手元に来たら、この1枚だけで最初の確認を始められるようにしたもの。所要時間の目安は20〜30分。**初回は ★ の項目だけでよい**（★ 以外は時間があれば）。結果欄には ☑（問題なし）／✗（問題あり。症状を一言）／—（未確認）と、撮った証拠のファイル名を書く。

**今回の確認で分かること・分からないこと**: 仕組み（キャリブレーション、周回ごとの部屋の置き直し、操作、負荷、復旧）が実機で成り立つかを確かめる。今の部屋の問題（遮蔽→脱出）は仕組みの確認用の仮のもので、**謎解きや突発性の体験の評価はこの確認では行わない**（問題の中身はユーザーが検討中）。各項目の「参照」は `Docs/UNITY_ACCEPTANCE.md` の章・手順。「本書」とある項目は受入手順書に詳しい手順が無く、この表の記述が確認基準になる。

## 0. 準備（5分）

1. PC で **Meta Horizon Link** を起動し、Quest 3 / 3S を USB（Link）または Air Link で接続する。Quest 側で Link を有効にし、Link のホームが HMD に出ることを確認する。
2. OpenXR の既定ランタイムが **Meta Horizon Link** になっていることを確認する（Link アプリ → 設定 → 一般 → OpenXR ランタイム）。
3. プレイ領域（ガーディアン）を **体験空間（既定 1.6m 四方）より広く**設定し、中央付近に立つ。体験空間の大きさは `%USERPROFILE%\AppData\LocalLow\LoopRoomDemo\The Room Before\play-area.json` の `areaSize`（m）で事前に変えられる（初回起動で既定値のファイルが作られる。編集後はアプリを起動し直す）。
   - Air Link の場合: PC と Quest を同じ 5GHz/6GHz の Wi-Fi（できればルーターの近く）につなぎ、Quest の設定 → Link で Air Link を有効にする。
4. PowerShell で正本のフォルダに移動し、機種を付けて起動する: `.\Start-DeviceCheck.ps1 -Device Quest3S`（または `Quest3`）。セッションログのフォルダも開く。
   - 「スクリプトの実行が無効」と出たら: `powershell -ExecutionPolicy Bypass -File .\Start-DeviceCheck.ps1 -Device Quest3S`
   - ビルドが無いと言われたら、表示される Unity のコマンドでビルドしてからやり直す。
   - 起動時の警告を確認する: 「未コミットの変更を含むビルド」「現在の HEAD とビルドの commit が異なります」「build-info なし」が出たら、その文言を記録に残す（どのソースのビルドで確かめたかを後で特定するため。`Builds/Windows/build-info.json` と起動スクリプトの記録 `session-notes.txt` に残る）。

## 2b. 周回ごとの部屋の置き直し

周回の始まり（暗転中）に、部屋は体験者の今の位置と向きに合わせて置き直される（XR 原点は動かさない）。前方の範囲が体験空間に収まらないときだけ、正面の向きが補正される。PC の運営表示（F2）と `Player.log` の `PlaceRoom … corrected=… diff=… fits=…` の行で確かめられる。

| # | 確認すること | 参照 | 結果 |
| --- | --- | --- | --- |
| ★R1 | 中央付近に立ったまま周回する: 毎回ほぼ同じ構図で始まり、机と取っ手の位置関係が毎回同じ（`corrected=False`） | 本書 | ☐ |
| ★R2 | 少し（0.2m 程度）ずれた位置・向きで死ぬ: 次の周回が今の位置を基準に始まる。違和感・酔いの有無を記録 | 本書 | ☐ |
| R3 | 大きく（0.4m 以上）ずれた位置で死ぬ: 正面が補正される（`corrected=True`、`diff` が補正角）。**補正後に正面（机と時計）へ向き直れたか、かかった時間、始まりの時計の音で正面の方向が分かったか**を記録 | 本書 | ☐ |
| R4 | 体験空間の端（中心から約0.7m 以上）で死ぬ: PC の運営表示に「**安全な向きなし: 中央へ / C で再設定**」が出る（`fits=False`）。**出たら運営は体験者を中央付近へ戻すか、C でキャリブレーションし直す**。部屋は頭の向きのまま置かれ続行するので、周囲の安全を運営が確認する。セッションログの `noFitPlacements` に回数が残る | 本書 | ☐ |

## 5. 証拠の残し方

- **HMD の画面**: Quest のスクリーンショット（Meta ボタン＋トリガー）、または Link の画面キャプチャ。
- **PC 画面**: `Win + Shift + S`。観客用の画面は F2 を OFF にしてから撮る。
- **セッションログ**: `%USERPROFILE%\AppData\LocalLow\LoopRoomDemo\The Room Before\Sessions\*.json`（起動スクリプトが開く）。`outcome`、`elapsed`、`timings.enforcePlayLimit=false`、`frames`（平均・P95・最大・落ち。`dropped` は目標のフレーム時間の1.5倍を超えたアプリ側のフレーム数で、`frames` の総数も一緒に見る）、`noFitPlacements` を確認する（第8・9章）。
- 撮ったファイルとこの表の結果は、起動スクリプトが作る `Collaboration/evidence/<日付>-device-check/` に置く（AI が記録と共有をする）。

## 困ったとき

- 部屋が出ず PC 画面だけ動く: Link がつながっていない（desktop 表示）。Link を確認し、「R: 再準備（運営）」が出ていれば R。
- 床が低い／高い: ガーディアンの床の高さを設定し直してから R。
- 枠が足元からずれる・向きが違う: C でキャリブレーションをやり直す。
- Air Link で映像が途切れる・カクつく: Wi-Fi の混雑を避ける（5GHz/6GHz、ルーターの近く）。改善しなければ USB（Link ケーブル）で同じ確認をして比較する。
- R を押しても VR にならない: アプリを終了して起動スクリプトからやり直す。`Player.log`（Sessions フォルダの一つ上）を AI に渡す。
