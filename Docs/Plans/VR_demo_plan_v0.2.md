# 死に戻りVRデモ — 企画 v0.2（2026-09-24、ユーザーと計画担当 Claude Opus 5.5 の合意）

v0.1（`VR_demo_plan_v0.1.md`）はシステム構成・状態管理・検証方法の根拠として残す。本書は体験の企画を更新し、v0.1 と食い違う点はこちらを正とする。未決定の点は「保留」と明記し、推測で埋めない。

## 1. 体験の核

> **気づいたら死んでいて、気づいたら戻っている。その繰り返しの中で、2m四方の部屋の意味が少しずつ分かっていく。**

参考: ヨルシカ「あぶく」の MV（ホテルの一室で目覚め、数秒後に撃たれて同じ椅子で目覚め直す。部屋の物を使った試行錯誤の末、脱出する）。

死に戻り体験を支える2つの要素（ユーザー定義）:

1. **即時性** — 死に戻りのあと、自分の死を理解できないほどの速さで次のループへ入る。死亡画面・リトライ表示・待ち時間を置かない。
2. **突発性** — 分かりやすい事象を経て死ぬのではなく、突然ループへ入れられる。死の直前に予告を出さない。

この2つを合わせ、短時間の死に戻りを繰り返しながら、時間の経過とともに「為すべきこと」を理解し、達成感を味わえる体験にする。**わずか2m四方の空間でこの体験ができること**を魅力とする。

### 突発性と達成感を両立させる原則（計画担当の提案、合意済み）

- 死ぬ瞬間は予告しない。ただし**同じ行動をとれば毎回同じ原因・同じタイミング**で死ぬので、観察すれば必ず分かる（理不尽にしない）。
- 時計の音は「戻った」ことを知らせるが、死因までは説明しない。死因は、平常時から見える物の関係や、操作によって生き延びる時間が延びるという結果から学べるようにする（Astra 指摘）。
- **死の痕跡は音で伝える**: ループの始まりと同時に、必ず同じ時計の音が鳴る。「戻った」ことを知らせる**専用の合図は時計の音だけ**とする（合意済み。部屋の向きの変化や時計表示の巻き戻りも結果として目に入る）。

## 2. 空間 — 定位置から始まる部屋（2026-09-24 改訂、合意済み）

経緯: 当初は「部屋を中心軸で90°単位に回して空間を確保する」案だったが、ユーザーとの協議で次の方式に改めた（90°回転案は廃止）。

- **ループが始まるたびに（暗転の間に）、仮想の部屋全体を体験者に合わせて置き直す。** 体験者の今の足元が部屋の「定位置」に、今向いている方向が部屋の「正面」になる。体験者は戻る動作をせずに、毎回同じ場所・同じ向きから始まる（MV の「同じ椅子で目覚める」）。即時性を損なわない。
- **動きの制限**: 問題に必要な動きは「定位置から前方 ±45° の扇形、半径 0.4〜0.5m 以内」だけ（前へ一歩、前の左右に手を伸ばす程度。当初の前方半円は、角で収まらないことが実装時に分かり修正）。背後・大きな横移動は使わない。**この制限のままどこまで良い体験になるかを実機で実験し、その結果で変更する**（合意）。
- **安全の判定**: 現実に動ける範囲は **1.6m 四方**（合意）。ループ開始時、体験者の向きを正面にしたときの前方の領域がこの範囲（余裕を引いた内側）に収まるかを確かめ、収まらない場合だけ、収まる向きのうち今の向きに最も近い向きを正面にする。四隅でも中心方向なら前方に 1m 以上残るので、収まる向きは必ずある。
- 正面の向きを変えた場合に向き直りやすいよう、**始まりの時計の音は部屋の正面から鳴らす**（死の痕跡と向きの手がかりを兼ねる）。
- セッション開始前に、運営がプレイエリアの中心と向きを合わせる（体験者が中央に立って正面を向いた状態で運営キー）。
- XR 原点は動かさない（体の位置・姿勢は巻き戻さない）。置き直すのは仮想の部屋だけで、動きは暗転中なので見えない（酔い対策）。仮想の壁が現実の境界の外に来ることはあるが、必要な動きは前方の領域に限るので壁に触れに行くことはない。Quest の境界表示は無効にしない。
- 定位置の前方の、動いてよい範囲に**ラグ（敷物）**を敷いて示す。
- 実機での実験項目: 置き直しに気づくか・違和感、向きの補正が起きたときの向き直りの時間、前方0.4〜0.5m で問題が成立するか、境界表示との関係、酔い。

## 3. 部屋（合意済み）

- 雰囲気を作り込まない、**よく見るシンプルな部屋**。違和感のない部屋で突然死ぬことが突発性を生む。
- 部屋の種類は将来**複数**用意する。**まずはワンルーム**（ベッドや机、窓、扉、照明スイッチ、時計などがある普通の部屋）。
- クオリティ第1弾（task014）の暗い照明・霧・「第零室」の看板・帽子の人影は、この方針に合わせて作り直す。部屋の造形の仕組み、文字の奥行き描画、合成音の仕組みは活かす。

## 4. 死に方と死の見せ方

- 死に方の軸は**いろいろ混ぜてよい**（合意済み）。銃（姿の見えない射手、扉越し・窓越しなど）に限らない。実際に人を出すと質量感が出せない可能性があるため、姿を見せない死に方を優先候補とする。
- 死の見せ方は2種類を混ぜる（ユーザー案）:
  - **何かが起きたと分かる死**: 視界が少し上を向き、暗転する。VR ではカメラを強制的に動かせないため、**部屋のほうを約0.1〜0.15秒だけ下へ傾けてから暗転**する方式を候補とする（酔いの実機確認が条件。**未確定**）。
  - **突発の死**: 何の前触れもなく即暗転する。
- 暗転から次のループまでは現在 0.16秒。即時性の目標として維持する。

## 5. 問題（**保留**）

- 一つの問題を抜けると、また一つの問題が浮上する構成にする（合意済み）。
- 空間が狭いため、**体を大きく使う問題にはしない**（合意済み）。踏み出す・よける・しゃがむ・手を伸ばす程度。ダッシュ・飛び込み・倒れ込み・後ろ向きの踏み出しは求めない（v0.1 を維持）。
- 必ずしも「銃から逃げる」問題でなくてよい。**具体的な問題の内容は保留**（ユーザーが後で考える）。計画担当が候補を出す場合は、ユーザーの判断材料として出し、合意なしに採用しない。
- 現在の試作（遮蔽→脱出の2段階）は、仕組みの検証用として残す。

## 6. 体験の長さ

- 今は決めない（ユーザー判断で計画担当に一任）。**当面の目安は 5〜10分、問題は3〜4段階**。180秒の上限は外したまま（task007）。

## 8. 次の段階（計画担当の提案、ユーザー確認後にタスク化）

1. **仕組みの試作（問題の中身に依存しない部分）** — まずは**ラグ・時計・仮の操作対象・最低限の家具**だけで、位置合わせと回転を実機で確かめる（家具を揃えるのはその後。Astra 提案）。候補が無いときの処理、位置合わせの失効条件、復帰時の家具との重なり、暗転・回転・音・入力再開の順序も含める
   - プレイエリアの中心と向きの位置合わせ（開始前、運営キー）
   - ループごとの部屋の置き直し（前方の領域の判定と向きの補正、暗転中）→ task017・task018
   - 始まりの時計の音（空間化、部屋の決まった位置）
   - ワンルームの部屋（安全範囲の内側に置くラグ、普通の家具、手の届く範囲の配置）
   - desktop の自動実行で証拠を撮れる状態を維持する
2. **実機で確かめる**: 回転後の向きの分かりやすさ、酔い、ラグと境界の一致、時計の音で向きが分かるか。
3. **問題の設計**（ユーザーのアイデアが出てから）→ まず1段階で「予告なしでも学べる」を確かめ、次に2段階の連鎖、成立してから3〜4段階へ（Astra 提案）。部屋を傾ける演出の評価は、回転の評価とは分けて行う。
   - Astra が出した候補（判断はユーザー）: 窓のブラインドを先に閉める／卓上スイッチで致死的な通電を止める／手元の補助錠を掛ける／自動装置に使われる危険な小物を安全な物に替える／卓上ラジオで見えない脅威の注意をそらす。詳細は `Collaboration/reviews/astra-plan-v0.2-20260924.md`。
4. 部屋の種類を増やす。
