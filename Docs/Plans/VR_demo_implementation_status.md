## Unityで止まっている理由

この自動実行環境では、Unity EditorからローカルPackage ManagerへのIPC接続が30秒でタイムアウトした。ログは `Could not establish a connection with the Unity Package Manager local server process`。既定設定、作業用キャッシュ、明示した作業用ログ保存先で確認したが、Editorのインポートへ進まなかった。

キャッシュ・ログの書き込み先を作業フォルダーへ変更する公式の設定を試した。通信制限の解除、プロキシ解除、権限昇格は実行していない。これだけで利用者が通常起動するUnityでも同じ問題が起きるとは断定しない。

次は通常のUnity Hubから納品フォルダーのプロジェクトを開き、依存解決とConsoleエラーの有無を確認する必要がある。エラーが出た場合は最初のエラーを起点に修正する。メニューからの設定後、Quest 3を装着して確認する。

## Claude Codeとの連携

Claude Codeのインストールを確認した。企画者からの許可を受け、状態モデルだけを渡し、ツールなし・ファイル編集なしのレビューを依頼した。90秒でタイムアウトし、レビュー結果は得られなかった。Claudeが確認済みとは扱っていない。

通常の環境で再レビューする場合に使える依頼文を、プロジェクトの `CLAUDE_REVIEW_REQUEST.md` に用意した。

## 初期仕様としての限界

- 1場面だけ。遮蔽の可否は操作状態で判定し、頭・身体形状への精密な弾道判定は未実装。
- 敵は時間と遮蔽状態による固定の侵入・回り込み。本格的な視認・聴覚・自由戦闘は後工程。
- デスクトップ操作は独自の簡易確認モードで、公式XR Interaction Simulatorの同梱・セットアップは未実施。
- 暗転0.16秒は設計値で、HMD上でその時間を実測したものではない。
- 2m四方、到達範囲、体験の快適さ、3分の展示運用は実機評価が必要。
- 初期デモの成功が簡単すぎる／初見には難しすぎる可能性がある。試遊で調整する。

## 最初の試遊で確認する順番

1. HMDなしで、無操作で戻ること、Spaceで防げること、Eで出口が使えること。
2. Quest 3で頭・左右の手が追跡され、グリップで操作できること。
3. 復帰時に身体の位置・姿勢が強制変更されず、次の操作ができること。
4. 速さ・手の届き方・追跡喪失時の停止・描画負荷。
5. 最初の死の解釈、次に試す行動、突破できた達成感。
